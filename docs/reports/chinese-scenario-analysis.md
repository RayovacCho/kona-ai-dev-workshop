# 中文序列化场景分析

## 结论

现有正式 JMH 同时包含成对的英文与中文载荷。对任务 2.1 基线和任务 2.3 最终结果进行
配对后，可以得到三点结论：

1. 对象字段缓存优化对中英文写路径同样有效。`GRAPH_CHINESE serialize` 的分配量从
   18,664 B/op 降至 16,320 B/op，与英文对象图相同，均下降 12.56%。
2. 中文对象图的序列化耗时高于英文对象图：基线差异为 +17.42%，优化后为 +12.46%。
   由于两类样本的字符数和编码后字节数不同，这只能说明当前中文工作负载成本更高，不能
   单独归因为中文字符编码。
3. 中文对象图反序列化分配量比英文高约 14.7%，而本轮优化没有修改读取路径。这是下一轮
   中文场景性能分析更值得关注的方向。

## 可重复分析

从仓库根目录运行：

```bash
make analyze-chinese
```

脚本直接读取已提交的 JMH JSON，按操作配对 `SMALL` / `SMALL_CHINESE` 和
`GRAPH` / `GRAPH_CHINESE`，验证指标单位和场景完整性后输出中文 Markdown 表格。默认同时
分析任务 2.1 基线与任务 2.3 最终结果，也可指定其他结果：

```bash
python3 scripts/analyze-chinese-jmh.py \
  --baseline /path/to/baseline.json \
  --optimized /path/to/optimized.json
```

## 下一轮建议

- 记录每种载荷的序列化字节数，将“内容更多”与“单位字节处理成本”分开；
- 新增等字符数、等 UTF 编码字节数两组受控文本，避免语言、长度和字节数三个变量混杂；
- 对中文反序列化使用 JFR、async-profiler 或同等工具定位额外分配，重点检查字符串解码与
  临时字符/字节缓冲；
- 正式性能结论仍以同机、相同 JMH 参数的完整 A/B 为准，不根据中英文横向比较直接宣称
  某种语言导致性能变化。
