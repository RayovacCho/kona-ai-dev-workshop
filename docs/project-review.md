## 剩余风险与建议

### 中等：jtreg 证据主要是摘要

正式 JMH 具有原始 JSON、环境和二进制哈希；jtreg 的完整报告只保留在 JDK 构建目录，仓库
提交的是测试数量和结果摘要。若评审要求完全离线审计，可在下一次复跑后归档压缩后的
`text/summary.txt`、`JTreport/text/stats.txt` 或等价摘要，并记录 SHA-256；不建议提交整个
JDK 测试工作目录。

### 已收敛：延迟收益具有场景边界

2026-09-10 已按 A/B/B/A 交错执行预分配缓冲与长生命周期流 focused 基准，并把单次测量
从 1 秒延长到 3 秒。分配下降再次稳定重现；英文 `GRAPH` 在两种操作的两组相邻配对中均
小幅变慢，复用流平均约 +5.37%，说明没有明显 GC 压力时，每对象控制开销确实可能抵消
廉价 TLAB 小数组分配。中文图和大数组延迟仍不确定。结论应保持为“GC 敏感深/宽图更可能
净受益；延迟敏感的少引用字段浅/扁平图是权衡”，详见任务 2.3 报告和 focused 原始归档。

### 低：联网 JBS 路径没有持续集成验证

单元测试使用固定响应，真实 JBS 查询依赖外网并会降级为手工 URL。可增加一个默认关闭的
联网 smoke test，定期检查 REST 响应形状；不要让外部服务可用性阻塞本地崩溃分析。

### 低：源码与 workshop 分属两个仓库

这符合当前仓库边界，但首次阅读者必须同时访问 Kona fork 才能重建 JDK 修改。提交作业时
应固定 PR、完整提交号和分支，并避免只引用可移动的分支头。
